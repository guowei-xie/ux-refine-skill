# 方案模式库

这些是针对常见问题的成熟做法。每个模式写清：解决什么、怎么做、适用条件、代价。
给用户方案时，不要照搬，要结合阶段 0 了解到的用户、高频任务与约束调整；
有多个模式都可行时，把它们作为选项交给用户选，并写出你的推荐和理由。

## 总原则：先改设计，最后才加提示

想要「加一个提示 / 说明 / 引导」来解决问题时，先依次问：
1. 能不能让错误的操作做不出来？（约束：禁用、限定输入类型、选择器代替手输）
2. 能不能让正确的做法一眼可见？（示能与位置：高频操作外露、主操作唯一且醒目）
3. 能不能沿用用户已有的习惯？（惯例：同类页面同一结构、同一操作同一交互）
4. 能不能让结果立刻可见？（反馈：实时预览、操作后界面直接更新）

四个都做不到，再加提示，并且把提示放在需要它的那一刻、那个位置，而不是常驻横幅或培训文档里。
方案里如果出现「增加提示文案」，要说明为什么上面四条都不适用。

## A. 导航与信息架构

### A1 按任务重组菜单
- **解决**：菜单按开发模块命名、用户找不到功能。
- **做法**：列出所有页面 → 和用户一起按「用户要完成什么」聚类（卡片分类法的轻量版）→
  每组起一个用户语言的名字 → 一级 5–7 组，组内不超过 7–9 项，超出再分二级。
- **适用**：菜单项 > 20 或用户普遍反映「找不到」。
- **代价**：老用户需要重新适应；路由地址最好保持不变，只改菜单结构，减少书签和外链失效。

### A2 侧边分组 + 折叠
- 一级分组作为可折叠的标题，适合功能多但分组清晰的后台。Ant Design Pro、多数云控制台采用此方式。

### A3 顶部一级 + 侧边二级
- 一级是业务域（如「交易」「商品」「用户」），切换后侧边显示该域下的功能。适合业务域边界清晰、
  用户通常只在一个域内工作的系统。代价是跨域操作要多一次切换。

### A4 全局搜索 / 命令面板
- 补充而非替代菜单：`Ctrl/Cmd + K` 搜功能名与常用对象。适合页面极多、专家用户多的平台，开发成本低、收益明显。

### A5 常用 / 最近访问
- 首页或菜单顶部放「最近访问」「我的收藏」，缓解深层级问题。低成本速赢。

### A6 新旧页面收敛
- 新旧两版并存时：明确一版为准，旧版加跳转提示并设下线日期，而不是长期并存。

## B. 页面模板化

后台系统 80% 的页面是几种类型，为每种类型定一个模板组件，是解决一致性问题的根本办法。

### B1 列表页模板
- 结构：页头（标题 + 主操作）→ 筛选区（常用条件外露，其余收进「更多筛选」）→
  工具栏（批量操作、导出、列设置）→ 表格 → 分页。
- 约定：筛选条件与分页同步到 URL；空态区分「无数据」与「无筛选结果」并提供「清空筛选」；
  行操作不超过 3 个，其余收进「更多」。

### B2 详情页模板
- 结构：页头（对象名 + 状态标签 + 主操作）→ 关键信息摘要 → 分组信息卡片或标签页 → 操作记录。

### B3 表单页模板
- 新建与编辑复用同一表单组件；字段分组；长表单配锚点；底部固定操作栏。

### B4 落地方式
- 先抽模板组件，在 1–2 个页面上验证，再批量迁移。迁移顺序按访问频率从高到低。

## C. 设计 token 与样式统一

### C1 收敛 token
- 用 `style_inventory.py` 的结果，把发散的取值收敛到一套刻度：颜色（主色、功能色、5–7 级中性灰）、
  字号（如 12/14/16/20/24）、间距（4 的倍数）、圆角（1–2 种）、阴影（2–3 级）。
- 有组件库的，优先通过组件库的主题机制（Ant Design `ConfigProvider` theme、Element CSS 变量、
  MUI `createTheme`）落地，而不是另起一套。
- 以 CSS 变量或主题对象为唯一来源，替换硬编码值。

### C2 防止复发
- 加 stylelint 规则禁止硬编码颜色，或在代码评审清单里加一条。可选，问用户是否需要。

## D. 反馈与状态

### D1 异步操作四态
- 每个请求都要处理：进行中（按钮 loading + 禁用，防重复提交）、成功（轻提示或界面直接更新）、
  失败（可理解的原因 + 下一步怎么办）、空。
- 可抽一个统一的请求 hook 或封装，把 loading 和错误提示默认做好。

### D2 空状态设计
- 首次使用空态：说明这里会有什么 + 引导创建的按钮。
- 筛选无结果：说明 + 「清空筛选」。
- 加载失败：说明 + 「重试」。

### D3 错误文案
- 前端把常见错误码映射成用户语言；未知错误给「稍后重试 / 联系谁」+ 可复制的请求 ID，
  不直接展示后端原始报错。

### D4 长任务
- 导入导出等异步任务：提交后立即反馈「已开始」，提供任务中心或通知查看结果。

## E. 效率提升

- **E1 行内编辑 / 快捷操作**：高频改单个字段（状态、负责人）的，在列表行内完成。
- **E2 批量操作**：表格多选 + 批量工具栏，选中后显示已选数量与可执行操作。
- **E3 状态保持**：筛选、分页、标签页状态进 URL；从详情返回列表时恢复滚动位置。
- **E4 智能默认值**：记住用户上次的选择；表单根据上下文预填。
- **E5 抽屉代替跳转**：查看或快速编辑用抽屉，保留列表上下文。适合字段不多的场景，复杂详情仍用独立页面。

## F. 表单

- **F1 实时校验**：失焦即校验，错误显示在字段下方；提交时滚动到第一个错误。
- **F2 合适的控件**：枚举 ≤ 5 用单选、> 5 用下拉，可搜索的大集合用带搜索的选择器，日期用日期选择器。
- **F3 分组与渐进披露**：高级选项默认收起。
- **F4 离开提醒**：有未保存修改时拦截离开。

## G. 防错

- **G1 确认分级**：可撤销的操作不确认，改用「已删除，撤销」提示；不可撤销的操作弹窗确认并写明后果；
  影响重大的（批量删除、删除有关联数据的对象）要求输入名称确认。
- **G2 危险操作视觉隔离**：红色或描边样式，与常用操作拉开距离或收进「更多」。
- **G3 软删除 + 回收站**：需要后端配合，作为选项提给用户。

## H. 迁移与过渡

改变用户习惯的方案（菜单重组、按钮挪位）要考虑过渡：
- 上线公告或首次进入的引导提示，说明「X 移到了 Y」。
- 旧路由保留重定向。
- 灰度：先对部分用户或内部用户开放，收集反馈。
- 按模块逐步替换，而不是一次性全量改版。

是否需要这些过渡手段、做到什么程度，问用户。内部工具通常一条公告即可，外部客户产品要谨慎。
